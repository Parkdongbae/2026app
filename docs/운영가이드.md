## 새 파일이 올라오는 방식 (2026-11-27 추가)

1. **방문할 때 자동 반영 (주된 방법)**: 누군가 사이트를 열면 서버(`site/api/refresh.js`)가 제출 폴더에 새 파일이 있는지 확인하고, 있으면 바로 동기화를 시작합니다. 1~2분 뒤 화면이 저절로 새로 고쳐집니다. (최근 3분 안에 실행된 적이 있으면 건너뜀)
2. **즉시**: `배포.bat` 더블클릭, 또는 GitHub Actions 페이지의 `Run workflow`.
3. **GitHub 예약 실행(10분마다)**: 무료 저장소에서는 몇 시간씩 늦거나 건너뛰는 일이 많아 보조로만 둡니다.

자동 반영에는 Vercel 환경 변수 `GITHUB_TOKEN`(저장소 `2026game`·`2026app` 의 Actions 읽기·쓰기 권한, 이름 `2026-gallery-sync`)이 필요합니다. 토큰 만료일(약 1년)이 지나면 자동 반영만 멈추고, 새 토큰을 만들어 두 Vercel 프로젝트(`dongshin-game-2026`, `dongshin-app-2026`)에 같은 이름으로 바꿔 넣으면 됩니다.
상태 확인: 주소 끝에 `/api/refresh` 를 붙여 열면 `tokenOk: true` 가 보여야 정상입니다.

## 학생이 웹앱을 추가했을 때

- **아무것도 안 해도 됩니다.** 10분마다 제출 폴더를 확인해 자동 반영합니다(보통 10~20분).
- **지금 바로**: `D:\2026app\배포.bat` 더블클릭, 또는 [Actions](https://github.com/Parkdongbae/2026app/actions/workflows/sync.yml) → `Run workflow`.

## 제출 규칙 (학생 안내용)

1. 웹앱이 들어 있는 **HTML 파일 1개**를 올린다. 파일 이름 끝은 `학번이름.html` (구글 설문으로 내면 보통 자동으로 붙음).
2. AI 대화 화면을 통째로 저장한 파일은 안 된다 → 갤러리 맨 위 "다시 제출이 필요해요"에 이름이 뜬다.
3. 고쳐서 다시 낼 때는 새 파일을 그냥 올리면 된다. 같은 앱의 수정본이면 새 파일만 보이고 도움돼요는 유지된다(`UPDATE` 배지).
4. 서로 다른 앱은 여러 개 내도 된다(`학번-2`, `학번-3` …).

## 분류

제목·설명·화면 글자를 보고 자동으로 나눕니다: 📚 공부 / ⏰ 시간·계획 / 💪 건강·운동 / 🏠 생활 / 🛠️ 도구 / ✨ 기타.
제목에 분류 낱말(예: 건강, 타이머, 단어)이 있으면 제목이 우선입니다.

틀리면 `overrides.json` 으로 고칩니다 (GitHub 웹에서 연필 아이콘으로 수정 → 저장하면 자동 반영):

```json
{
  "3105": { "category": "health" },
  "3108": { "title": "수학 시각화 스튜디오", "desc": "그래프와 도형을 움직이며 배우는 수학 앱" },
  "3113": { "hide": true }
}
```

| 키 | 값 |
|---|---|
| `category` | `study` `plan` `health` `life` `tool` `etc` 중 하나 |
| `title` | 카드 제목 |
| `desc` | 카드의 한 줄 설명 (자동 설명이 어색할 때) |
| `hide` | `true` 면 스토어에서 내림 (도움돼요 기록은 유지) |

## 도움돼요 (좋아요)

- 학교 계정(`@dongshin.ms.kr`)으로 로그인해야 누를 수 있고, 앱마다 1번(다시 누르면 취소).
- **Firebase는 게임 갤러리와 같은 프로젝트**(`dongshin-game-2026`)를 씁니다. 저장 칸만 다릅니다: 게임 = `likes`, 웹앱 = `appLikes`.
- 보안 규칙은 **게임 갤러리 저장소의 `firestore.rules` 한 파일**에 둘 다 들어 있습니다. (이 저장소에서 따로 배포하면 게임 쪽 규칙이 지워집니다.)
- 규칙을 고쳐 올리는 방법: `D:\2026game\firestore.rules` 를 고친 뒤, **Firebase 콘솔 → 데이터베이스 및 스토리지 → Firestore → 규칙** 탭에 파일 내용 전체를 붙여넣고 **게시**.
  터미널의 `firebase login` 은 회사 계정 로그인(penz.kr) 화면에서 막힐 수 있으므로 콘솔 방법을 씁니다.
  콘솔에서 "프로젝트가 존재하지 않거나 권한이 없습니다"가 나오면 브라우저가 다른 계정으로 로그인된 것 → 오른쪽 위 프로필에서 **doandong@penz.kr** 로 바꿉니다.
- 누가 눌렀는지·초기화: Firebase 콘솔 → Firestore Database → `appLikes`.

## 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| 새 웹앱이 30분 넘게 안 올라옴 | Actions 페이지에서 빨간 표시 확인 → `배포.bat` |
| Actions 가 아예 안 돎 | 60일 무활동 시 GitHub가 예약 실행을 끔 → Actions 페이지의 `Enable workflow` |
| "폴더 화면을 읽지 못함" | 제출 폴더 공유가 "링크가 있는 모든 사용자"인지 확인 |
| "폴더가 갑자기 비었음" | 일시 오류면 다음 실행 때 저절로 해결. 정말 모두 지웠다면 `site/games.json` 을 지우고 `배포.bat` |
| 로그인 팝업 오류 `unauthorized-domain` | Firebase 콘솔 → Authentication → 설정 → 승인된 도메인에 `dongshin-app-2026.vercel.app` 추가 |
| 도움돼요 "저장하지 못했어요" | 학교 계정인지 확인. 규칙이 빠졌으면 `D:\2026game` 에서 규칙 배포 |

## 폴더 구조

```
site/        스토어 화면 (index.html, config.js, games.json, assets/)  → Vercel: dongshin-app-2026
play/        학생 웹앱 파일 {ID}.html                                → Vercel: dongshin-app-2026-play
scripts/     sync.mjs (드라이브 → 저장소, 설명·분류 자동)
.github/     10분마다 sync.mjs 실행
overrides.json   분류·제목·설명 수정, 숨김
sync.config.json 제출 폴더 ID
배포.bat     즉시 배포
```
